# sns/queue/ ── ブログ公開 → SNS拡散の受け渡しキュー

`blog/scripts/publish_article.py` が**記事を新規公開するたびに自動で**
`YYYY-MM-DD-<記事ID>-<slug>.md` を1枚生成する場所。
「公開したのに拡散ゼロ」（2026年5〜7月の12記事が未拡散）を仕組みで解消するために作った。

## 運用ルール

1. **公開したブログセッションが、その場でX拡散セットを作る**
   （訴求分析・本文・返信・画像1〜4枚。キューを空欄のまま作業を終えない）
2. SNSセッション（またはユーザー）は `status: 原稿済み` のファイルから投稿し、
   投稿後に `status: 拡散済み` と投稿URLを追記する
3. 拡散済みファイルは月次で `sns/queue/done/` へ移動（削除しない＝実績台帳を兼ねる）

## ステータス

| status | 意味 |
|---|---|
| 未拡散 | 自動生成直後（原稿なし） |
| 原稿済み | X拡散セットあり・投稿待ち |
| 拡散済み | 投稿完了（投稿URLを追記） |

## X原稿の基準（sns/channels/x/SKILL.md 準拠）

- 140字以内・**数字を1つ入れる**（価格・時短分数・ROI日数など）
- リンク位置は目的別に選ぶ。ブログ流入を優先する投稿は本文へ記事URLを掲載し、認知・X内完結を優先する投稿は返信案へ分離。PRは投稿依頼・提供品・特別クーポン等がある場合のみ本文上部へ表示する
- 添付は実機写真または図解1〜4枚。複数枚は「数字→比較→内訳→注意」の順
- X投稿画面へ本文と画像をセットしてよいが、「ポストする」と返信送信はユーザーが行う
- 読者に偉そうな態度は記事と同じく禁止（blog/skills/writing.md §16）
