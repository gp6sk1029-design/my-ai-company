# 既存記事の全体更新

正本はWordPress本番。原稿の方が新しいという推測で上書きしない。
新規投稿・ドライランは従来どおり。既存記事の実更新だけ確認記録を必須にする。

1. 対象IDの現在の投稿を、既存の認証でGET `posts/<ID>?context=edit` から取得する。
2. JSONを `.operations-private/` 内に保存する。認証情報はJSONに含めない。
3. 本番の本文・画像・装飾と生成プレビューを比較する。意図しない削除を解消し、判断根拠を記録する。
4. 確認した原稿だけについて以下を実行する。未比較のまま確認記録を作ることは禁止。

```sh
python3 blog/scripts/article_update_guard.py --post-id <ID> --source <原稿md> --snapshot <本番JSON> --evidence '<本文・画像・装飾を照合した結果>'
```

5. 通常の `publish_article.py --update <ID> --publish` で更新する。
6. 公開ページで画像・装飾・リンクを確認して実操作結果を記録する。

原稿ハッシュ・控えのハッシュ・本番の内容/更新日時が一致しなければ停止する。
承認は24時間で期限切れ。本番もアップロード前と本文送信直前に読み直す。
ただしWordPress側の排他制御ではないため、送信直前の短い時間差まで完全に防ぐ保証はない。
他セッションや人間による同時編集は引き続き禁止する。

部分追記でも本番控えと差分確認は必要。全体更新ガードを回避するために別スクリプトへ切り替えない。
