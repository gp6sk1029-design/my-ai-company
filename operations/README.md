# 運営の入口

現在の優先順位・判断・実運用確認の正本は [CURRENT.md](CURRENT.md)。
部門のMEMORY.mdは過去の証拠・学びであり、古いTODOを自動で再開しない。

## 週次確認（週1回・15分）

1. `python3 tools/operations_check.py` でルール・正本・秘密情報の簡易検査を実施する。
2. `.operations-private/weekly_metrics.csv` の今週行に実測値と証拠URL/ファイルを記入する。
3. 未取得値は空欄のまま。0は実測で0の場合だけ記入する。公開数は下書き数と分ける。
4. CURRENT.mdの対応中は全社で3件まで。期限超過は理由と次の判断日を更新する。
5. 前週との変化から「続ける・変える・やめる」を1つ決め、CURRENT.mdへ記録する。

初回準備: `python3 tools/operations_check.py --init-metrics`。既存の数値は上書きしない。
月末は週次データを振り返り、作業量と成果を分けて評価する。
この手順は自動スケジュールではない。定期実行は別途ユーザー指定時のみ設定する。

## 完了判定

| 段階 | 必要な証拠 |
|---|---|
| 実装済み | 変更ファイルと差分 |
| テスト済み | テスト名・実行日・結果 |
| 実操作確認済み | 使用環境・操作・期待結果・実結果 |
| 運用開始 | 正本の場所・担当・使い方・復旧方法 |
| 効果確認済み | 実使用回数・成果指標・比較期間 |

「テスト済み」を「利用確認済み」に言い換えない。未確認の段階を残す。
AI連携は今回選んだモデルを明示して1回だけ短い依頼で実動作を確認し、応答・履歴・課金方式を照合する。
ユーザーがモデル未指定なら質問して待つ。司令塔の推測で補わない。

## 保存と採用

- ファイルはローカルへ通常どおり保存する。終了フックでは検査だけ行い、ステージ・コミット・pushはしない。
- GitHubへ送るときは検査、対象に応じたテスト、差分レビューを終え、対象ファイルを明示してコミットする。
- アプリ変更は `codex/` で始まる作業ブランチで扱い、mainへの採用前に実操作の結果を記録する。
- 検査は変更ファイルにある秘密値の代表的な形式と危険ファイル名を検出する補助。過去の全コミットは対象外であり、個人情報やあらゆる秘密を完全検出する保証はない。
- 外部サービスの認証・公開範囲が未確認なら新規公開/再デプロイを止める。アクセス制限を弱めて確認しない。
- 復旧は対象コミットを特定して差分を戻す。無関係な変更の破棄や一括リセットは禁止。
