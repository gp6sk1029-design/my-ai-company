# 外部脳 運用プロンプト（my-ai-company 最適化版・2026-06-16）

> 元になった「Claude × Obsidian 連携ルール」（外部公開プロンプト）を、my-ai-company の現行ルールに合わせて最適化したもの。
> **正本は `CLAUDE.md`。このプロンプトはその"外部脳の読み書き規律"を1枚に要約した運用ガイド**であり、新しいルールを足すものではない。
> ClaudeにもCodexにも同じ規律が適用される（Codexは `AGENTS.md` → `CLAUDE.md` 経由で従う）。

---

## 0. 前提：脳はもう在る（初期セットアップ不要）

このリポジトリ全体が既に「外部脳」。**`Knowledge/` `Decisions/` `Projects/` `Preferences/` のような新フォルダは作らない**（既存の置き場所と重複し、脳が二分割されるため）。
全体地図は `🏠 HOME.md`。Obsidianはこの脳を地図・グラフ・検索で見るための**人間用ビューア**で、ファイルは移動・変換しない。

---

## 1. 読む（セッション開始時に必ず）

1. `CLAUDE.md`（自動で読まれる）でモードと全社ルールを把握
2. 役割定義プロンプトが貼られていれば、その役割を完全に演じる（役割キーも記憶）
3. 着手前に**該当部門の `SKILL.md`（手順）→ `MEMORY.md`（学び・失敗）を読む**
4. 必要に応じて関連ファイルをキーワード検索して読む（handover/・reports/ も対象）

**スキップ可**：Obsidian/業務と無関係な単発質問（「今何時？」等）。

---

## 2. 書く（その場で・「後で書く」はしない）

会話の流れの中で都度保存する。**どこに書くかは下表で判断**（新フォルダは作らない）。

| 書く内容 | 置き場所（既存） | 形式 |
|---|---|---|
| 学び・成功/失敗パターン・解決したハマり・新発見・台帳・実績 | 該当部門の **`MEMORY.md`** | 「成功/失敗パターン」へ台帳形式で追記 |
| 手順・ルール・禁止事項 | 該当部門の **`SKILL.md`** | 既存の節に追記（毎回起動語で呼びたいなら Skill 化） |
| 一度きりの成果物（監査・レポート・図解） | **`reports/`** 等 | `YYYY-MM-DD-タイトル.md`（HTML/PDF可） |
| 次セッションへの申し送り | **`handover/`** | `tools/handover.py --role <役割キー>` で生成 |
| 他セッションへの依頼 | 各 `MEMORY.md`「他セッションへのTODO」欄 | チェックボックスで追記 |
| 重要な全社判断・方針決定 | `CLAUDE.md`（軽微は handover/reports） | 該当節へ。CLAUDE.md変更は慎重に |
| ユーザーの好み・作業スタイル | Claudeのmemory（`user`/`feedback`種別） | 横断する好みはmemory、部門固有はその`MEMORY.md` |

⛔ 機密・個人情報・収集元の生データはコミットしない（要約のみ。`.gitignore` と CLAUDE.md「やってはいけないこと」に従う）。

---

## 3. 書き込みの形式（既存に合わせる）

- **既存ファイル（MEMORY.md/SKILL.md）への追記**は、そのファイルの既存スタイル（日付＋カテゴリ見出し）に合わせる。独自フォーマットを持ち込まない。
- **新規の独立ノート**（HOMEや目次系）は、Obsidianのグラフを活かすため YAML フロントマター＋`[[wikilink]]` を使ってよい：
  ```
  ---
  date: YYYY-MM-DD
  tags: [tag1, tag2]
  ---
  本文。関連先は [[ファイル名]] でリンク。
  ```
- 既存の相対パスリンク（`blog/SKILL.md` 等）はそのまま有効。**一括で wikilink に変換しない**（段階導入）。

---

## 4. 失敗の活かし方（昇格フロー）

ユーザーから訂正を受け、かつ「①明示的な訂正 ②繰り返し起こり得る ③する/しないで書ける」を満たすときに記録する：

1. まず該当部門の `MEMORY.md`「失敗パターン」へ **原因＋対策をペアで**記録（対策のない記録はNG）
2. 同じ失敗が**2回以上 → `SKILL.md`「禁止事項」へ昇格**
3. 全部門で起こりうるなら **`CLAUDE.md` へ昇格**
4. 昇格させたら「この失敗を繰り返さないため○○にルール化しました」と伝える

記録の書き方の例：
```
YYYY-MM-DD: [一言で何を間違えたか]
- NG（やってしまったこと）：
- 正（次回の正しい対応）：
- 適用される状況：
```

---

## 5. 報告（サイレント保存は禁止）

読み書きしたら必ずユーザーに伝える。保存時は CLAUDE.md の**「💾保存しました」4点フォーマット**を使う：

```
💾 保存しました
- 何を：（例）リベ日課の保有自動取込の手順
- どこに：（例）MEMORY.md／SKILL.md／reports／handover のどれかを明示
- なぜ：（例）毎回手入力せず最新の保有で比較できるように
- 種別：⬜Skill化  ⬜手順(SKILL.md)  ⬜データ(MEMORY.md)  ⬜成果物  ⬜引き継ぎ
```

- Skill化したら「これは"○○"と打てば呼べます」と起動語を伝える。
- 別ファイルに分けて保存したら「○○とは分けて△△に保存しました」と区別を伝える。
- 読んだだけのときも、判断の根拠にしたファイルは「○○を参照しました」と一言添える。

---

## 6. 作業スタイル（CLAUDE.md準拠）

- 結論を先に。数値・金額・時間で語る。ROI（費用対効果）を意識する。
- シンプルで読みやすく。不要な装飾・冗長な説明は省く。既存の命名・パターンに合わせる。
- 動作確認・検証は自分で完結させ、ユーザーに丸投げしない。
- 毎タスク後に振り返りレポートを出す（省略しない）。

---

## 7. ClaudeとCodexの共存（競合予防）

- ClaudeもCodexも全ファイルを編集してよいが、**同時刻に同じ作業で並走させない（順番に使う）**。
- 開始時 `git pull`・終了時の競合マーカー検査（両ツールのフックに実装済み）で、逐次運用なら安全。
- Codexはこの規律を `AGENTS.md` → `CLAUDE.md` 経由で共有する。
