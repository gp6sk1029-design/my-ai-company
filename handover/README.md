# handover/ — セッション引き継ぎ書

## 何のフォルダか

長くなったセッションを安全に閉じて、新セッションで作業を再開するための「引き継ぎ書」を保存する場所です。

## いつ使うか

`tools/session_health.py` が **WARN（⚠️）または CRIT（🚨）** を出したとき。
具体的には：

- 画像枚数が25枚以上 → 2000pxエラーの危険
- セッションサイズが5MB以上 → 動作が重くなる
- ユーザー入力が30回以上 → 文脈管理が困難

## 引き継ぎ書を作る

```bash
# Claudeに「引き継ぎ準備して」と言うだけでOK
# または手動で：
python3 tools/handover.py
python3 tools/handover.py --title "blog記事3執筆"  # タイトル指定
```

`handover/2026-04-27-1430-xxx.md` が生成されます。

## 新セッションで復帰する

1. 新しいClaude Codeセッションを開く
2. 引き継ぎ書冒頭の「復帰用プロンプト」をコピペ
3. Claudeが自動的にSKILL.md・MEMORY.md・引き継ぎ書を読んで作業再開

## 引き継ぎ書のフォーマット

各書類には以下が含まれます：

- セッションの規模情報（容量・画像数・ターン数）
- 直近のユーザー指示10件
- 直近3時間で変更されたファイル一覧
- 直近のGitコミット
- 復帰用プロンプト（コピペ用）

## アーカイブ運用ルール（2026-05-24制定）

引き継ぎ書は時間とともに古くなり、現役のものを探しづらくなる。以下の運用で整理する。

### 配置ルール
- **handover/ 直下**: 直近30日以内の引き継ぎ書（現役・参照頻度高）
- **handover/archive/YYYY-MM/**: 30日以上経過した引き継ぎ書を月別に保管

### 棚卸しタイミング
- 月初（毎月1日前後）に当月初日基準で30日超のものを `archive/YYYY-MM/` へ移動
- CPOセッションの月次タスクとして実施

### 移動コマンド例
```bash
# 例: 2026年4月分をアーカイブ
mkdir -p handover/archive/2026-04
git mv handover/2026-04-*.md handover/archive/2026-04/
```

### アーカイブ前のチェック
- 重要な学びは該当部門の MEMORY.md（`blog/MEMORY.md` / `tools/ec/MEMORY.md` / `tools/MEMORY.md` 等）に転記してから移動
- 完全削除はしない（過去の意思決定の経緯を辿れるようにする）
