# handover/ — セッション引き継ぎ書

## 何のフォルダか

長くなったセッションを安全に閉じて、新セッションで作業を再開するための「引き継ぎ書」を保存する場所です。

## いつ使うか

`tools/session_health.py` が **WARN（⚠️）または CRIT（🚨）** を出したとき。
（2026-06-13改定：判定は「コンテキスト使用率」＝実測トークン÷モデルの窓サイズ）

- コンテキスト使用率 70%以上 → 警告ゾーン
- コンテキスト使用率 85%以上 → 危険ゾーン（約95%で自動圧縮が強制発動）
- 現コンテキスト内の画像 25枚以上 → API画像エラーの危険

警告時は診断が「圧縮（/compact）した場合の回復見込み・あと何回使えるか」も表示する。
**軽い作業の続きなら圧縮、大物作業・細部の記憶が重要なら引き継ぎ**を選ぶ。

## 引き継ぎ書を作る

```bash
# Claudeに「引き継ぎ準備して」と言うだけでOK
# 手動で実行する場合は --role（自分の役割キー）必須：
python3 tools/handover.py --role blog --title "blog記事3執筆"
```

> 🔴 **--role は必須（2026-06-12制定・役割の自己伝搬）**
> 自分の役割キーはセッション開始時に貼った「役割定義プロンプト」に書いてある。
> --role を省略すると活動内容からの推測になり、誤判定の実績がある（推測に頼らない）。

`handover/2026-06-13-0430-xxx.md` のようなファイルが生成されます。

## 新セッションで復帰する（2026-06-09改修：役割定義プロンプト方式）

1. 引き継ぎ書を生成すると、Claude（と handover.py）が**チャット画面にそのまま「🎭 役割定義プロンプト」を表示**する（ファイルを開く必要はない）
2. 新しいClaude Codeセッションを開く
3. 表示されたプロンプトをそのまま貼り付ける
4. Claudeが「○○セッション準備OK」と返したら、続きの作業を依頼する

役割定義プロンプトには「役割名・担当範囲・スコープ外・読むべきファイル・役割キー・次回引き継ぎ時の --role コマンド」が含まれ、役割が次のセッションへ自動で伝搬します。

## 引き継ぎ書のフォーマット

- メタ情報（トピック・推定役割・セッションID・健康状態・規模）
- **🎭 新セッション貼り付け用プロンプト（役割定義）** ← これを使う
- 直近のユーザー指示10件
- 直近3時間で変更されたファイル一覧
- 直近のGitコミット
- シンプル復帰用プロンプト（役割定義が不要な例外時のみ）

## アーカイブ運用ルール（2026-05-24制定）

引き継ぎ書は時間とともに古くなり、現役のものを探しづらくなる。以下の運用で整理する。

### 配置ルール
- **handover/ 直下**: 直近30日以内の引き継ぎ書（現役・参照頻度高）
- **handover/archive/YYYY-MM/**: 30日以上経過した引き継ぎ書を月別に保管

### 棚卸しタイミング
- 月初（毎月1日前後）に、その時点で30日超のものを `archive/YYYY-MM/` へ移動
- CPOセッションの月次タスクとして実施（月次サマリー記録とセット）

### 移動コマンド例
```bash
# 例: 2026年5月分をアーカイブ
mkdir -p handover/archive/2026-05
git mv handover/2026-05-*.md handover/archive/2026-05/
```

### アーカイブ前のチェック
- 重要な学びは該当部門の MEMORY.md（`blog/MEMORY.md` / `tools/ec/MEMORY.md` / `tools/MEMORY.md` 等）に転記してから移動
- 完全削除はしない（過去の意思決定の経緯を辿れるようにする）
