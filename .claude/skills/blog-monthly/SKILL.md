# ブログ月報スキル（2026-08-01 制定）

「分析が単発で終わる」問題（7/17の1回きり）を解消するための月次ルーチン。
リベシティ合宿の5大機能のうち「過去記事分析」を運用に載せた形。
月初（1〜5日目安）に1回実行する。所要約20分。

## 手順

### ① GSC（Google Search Console）── 検索の入口を見る
Claude in Chrome で `search.google.com/search-console` を開く：
- 検索パフォーマンス（過去28日）：クリック数・表示回数・CTR・平均掲載順位
- 上位クエリ 10件 と 上位ページ 10件 を記録
- **狙い目の発見**：表示回数が多いのにCTRが低いページ（タイトル改善候補）、
  掲載順位8〜20位のクエリ（リライトで1ページ目に上げられる候補）

### ② GA4 ── 読者の行動を見る
`analytics.google.com`（property: PTGL）で過去28日：
- ユーザー数・表示回数・平均エンゲージメント時間
- 流入元（Organic Search / Direct / Social の比率）
- ページ別表示回数 上位10記事
- ⚠️ 自分除外（3段構え）が効いているか、リアルタイムで軽く確認

### ③ 全記事の健康診断＋価格棚卸し（ローカルで1コマンド）
```bash
python3 blog/scripts/article_lint.py --all
```
- 🚫ERROR が出たら即修正（放置しない）
- ℹ️価格一覧を眺め、実売から大きくズレていそうな記事は
  Amazon/楽天の現在価格を確認して更新（取得日も更新）

### ④ 台帳に記録する
`blog/MEMORY.md` の「📈 月次分析台帳」へ追記（なければセクションを作る）：
```
### YYYY年MM月（記録日）
- GSC(28日): クリックX・表示X・CTR X%・平均順位 X位
- GA4(28日): ユーザーX・PV X・Organic X%
- 上位クエリ: …／上位記事: …
- 今月の決定: リライト対象=記事X（理由）／次ネタ候補=…
```

### ⑤ 決定を出して終わる（分析だけで終わらせない）
必ず以下の2つを**決定**としてユーザーに提示する：
1. **リライト対象1本**（表示多×CTR低、または順位8〜20位の記事）と改善案
2. **次ネタ候補1〜2本**（上位クエリの周辺needs・検索されているのに記事がない話題）

## 🚫 禁止事項

- スクリーンショットの多用（数値はテキストで読み取る。画像はセッションを圧迫する）
- 数値の記録だけで終わること（決定＝リライト対象と次ネタまで出す）
