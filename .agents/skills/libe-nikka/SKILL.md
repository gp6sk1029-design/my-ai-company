# リベ日課スキル

リベシティ研究を「毎朝ユーザーが起動するだけで更新できる日課」にする。朝会スキル（asakai）の研究部門版。

> ⚠️ このスキルは research 部門の運用ルールに従う。詳細手順は repo 内の
> `research/skills/collect.md`（収集・URL構造・礼節）/ `research/skills/digest.md`（学長要約・投資助言NG）/ `research/MEMORY.md`（台帳・規約承認記録）を正本とする。
> このSKILLはそれらを**毎日の手順に並べたオーケストレーター**。迷ったら上記を読む。

---

## 🚨 起動前チェック（満たさなければ中断）

1. **規約承認記録**：`research/MEMORY.md`「🚨 ユーザー承認記録（リベシティ利用規約）」が埋まっていること。空欄なら収集を**一切行わず**中断し、CPOセッションでの承認を促す。
2. **Codex in Chrome 接続**：`mcp__Claude_in_Chrome__list_connected_browsers` で接続確認。未接続なら「Chrome拡張を起動してください」と案内し中断。
3. **ログイン**：`https://libecity.com` がログイン済みか確認。未ログインなら「リベシティに手動ログインしてください」と案内し中断（🔴 パスワード入力は必ずユーザーが行う／AGENTS.md安全ルール）。
4. **収集手段は Codex in Chrome 必須**。headless cron・リモートagentでは不可（ログインセッション再利用が要るため）。これが「毎朝ユーザー起動型」である理由。

## 🎯 完了条件（DoD・これを満たすまで「完了」と言わない）

🔴 **リベ日課は「データ収集」だけでは絶対に終わらせない。下記すべてを満たして初めて完了：**

1. **収集**：Part A〜C のデータを取得（ノウハウ図書館／学長マガジン／高配当株）
2. **ビューア更新（必須・毎回）**：取得した新着を、対応する `research/reports/*.html` ビューアに**必ず焼き込む**。
   - 📚 ノウハウ図書館 → `ノウハウ図書館_人気記事ピックアップ.html` の `ARTICLES`＋`AUTO`
   - 📰 学長マガジン → `学長メソッド研究まとめ.html`（対象期間の要点へ丸ごと差替。過去分を画面に追記し続けない）
   - 💰 高配当株（更新があれば）→ `高配当株マガジン_月次比較ビューア.html`
   - 🦁 ポータル → `research/reports/index.html` の数字・日付（唯一の正本。名称付き旧HTMLは案内ページなので編集しない）
   - 各ファイルの footer/最終更新日も当日に
3. **台帳更新（必須）**：`research/MEMORY.md` の該当台帳にも追記（ビューアと台帳は必ず両方）
4. **Chromeで開く（必須）**：更新したビューア＋ポータルを `open -a "Google Chrome" "<file>"` で開く
5. **サマリー報告**：3セクションのサマリーを出す

⛔ **禁止**：「口頭まとめだけ」「データは取ったがビューアは後回し」で止めること。**収集したらその場でビューアまで仕上げる**のが本スキルの定義（2026-06-08ユーザー指示で徹底化）。ユーザーが明示的に「収集だけ」と言った時のみ例外。

## 実行手順（3パート・所要数分）

### Part A: ノウハウ図書館 人気記事の更新（毎日）

1. `library.libecity.com/search?days=3&sort_key=review`（直近3日・保存数順／1ページ24件）へ navigate。
   - 週次でまとめたい日は `days=7`、月初は `days=30` も併用してよい。
2. 記事カードを取得（collect.md §1 の innerText構造・§8.5 の3000字打切り対策＝`window.__ARTS`で全件保持→sliceで小分け）。
   - **本文は取らない**（タイトル＋反応数＋URLのみ。collect.md §3 一覧モード）。
   - ULIDは7字区切りで取得→HTML埋込時に区切り除去（出力フィルタ回避）。
3. `research/reports/ノウハウ図書館_人気記事ピックアップ.html` の `ARTICLES` 配列を**新着で差替**。
   - 仕分け（副業/お得/スキル・AI/その他）と自動化判定バッジ（go/part/no）は HTML内の `classify()` で**自動**。手で分類しない。
   - リンクは `onclick` フォールバック方式（`window.open`→`window.top.location`→`window.location`）を維持（collect.md 台帳メモの学習）。
4. **新規にランクインした記事・🟢ツール化向き判定の記事**があれば、サマリーで1〜2行に絞って報告。

### Part B: 学長マガジン 期間要約

#### B-0. 対象期間を先に確定する

- ユーザーが期間を指定した場合：その開始日〜終了日だけを対象にする。
- 期間指定がない場合：実行日を終点とする**直近1か月**を対象にする。
- `学長メソッド研究まとめ.html` は対象期間の要約へ**毎回丸ごと差し替える**。過去記事・過去Q&Aを画面へ累積しない。
- `research/MEMORY.md` には投稿ごとの全文・全Q&Aを増やさず、対象期間・主要テーマ・更新日を1行で記録する。既存の過去台帳は監査用アーカイブとして削除しない。
- 対象は `room_id=President-Tweet` の学長マガジンだけ。`room_id=President-investment-magazine` の内容はPart Cと高配当株専用ビューアで扱い、学長マガジンのビューアへ混在させない。

1. `room_id=President-Tweet` を**直接 navigate**（collect.md §8.6。サイドバークリックは切替らないことがある）。
2. **まず投稿の「日付＋見出し」を一覧化**（各日付行の直後の見出しを抽出）。学長はほぼ**毎朝ライブをやり、その日のうちに「【M月D日】ライブで拾いきれなかった質問に回答」を投稿**する（＝Q&Aは日付順では最新とは限らず、同日に複数投稿あり）。
3. 🔴 **投稿を種類で仕分けてから取る**：
   - **(a) ライブQ&A**「【M月D日】ライブで拾いきれなかった質問」→ 対象期間全体から代表的な問いを3〜5件選ぶ。全10問を日ごとに蓄積しない。
   - **(b) マガジン記事・ライブまとめ** → 対象期間全体を横断し、重複を束ねた主要テーマを5〜8件に整理する。
   - **(c) お知らせ・雑談**（◯周年・宿題チャレンジ告知等）→ **スキップ**（蓄積価値が低い）。
4. 取得・要約（digest.md §3 形式・**300字以内・自分の言葉・本文転載禁止**）：
   - Q&Aは `❓️` で split、各Qは対象投稿の `block` 内で抽出（§8 失敗パターン：別日のQ&A混同を防ぐ）。代表例だけを残し、回答は要点のみとする。
   - 🔴 **質問文は省略しすぎない**：「何を聞いているか」が単体で分かる形に（状況＋具体的な問い）。例「DX支援で独立。同友会へ入会すべき？」は短すぎ→「業務改善・DX支援で独立しオンラインで受注中。今後AI業務代行に挑戦したく、営業手段として地元の同友会・商工会への入会を検討。筋が悪い？」のように状況を残す（2026-06-04ユーザー指摘）。回答は短く、質問は分かる長さで。
   - 🔴 **要約は必ず2か所に同時反映する（片方だけ更新しない）**：
     1. `research/MEMORY.md`「📰 学長メソッド蓄積台帳」または進化ログに、対象期間と主要テーマを1行記録
     2. `research/reports/学長メソッド研究まとめ.html` を更新（ユーザーが実際に開く画面）＋footerの最終更新日を当日に
        - 表示は**対象期間の主要テーマと代表Q&Aだけ**に丸ごと差し替える。
        - 前回分・過去ログ・高配当株の内容は画面に残さない。
   - ⚠️ **なぜ2か所か**：台帳（データ）とビューア（表示）は別ファイル。台帳だけ更新するとビューアが古いまま＝「最新になってない」事故になる（2026-06-03発生・このルールで再発防止）。高配当株（Part C）も同様に台帳＋ビューア両方を更新する。
   - 新着がなければ「学長マガジン：新着なし」とだけ報告。

### Part C: 高配当株マガジン（月次・モデルPF更新）

1. **月初（1〜3日）＋月次回が未反映のとき** `room_id=President-investment-magazine` を navigate し、新しい「第N回 モデルポートフォリオ」回が出ているか確認。
   - 月途中で新回が無ければ「高配当株：月次更新待ち（前回=第◯回）」と報告して深追いしない。

2. 🟢 **最重要の近道（2026-06-08確立）：構成変更は本文テキストから読む（図のOCR不要）**
   - モデルPF回の本文に **「除外：◯◯、◯◯」「追加：◯◯、◯◯」** が**文章で明記**されていることが多い（第116回で実証）。
   - 取得：`get_page_text` で本文を取り、`/除外[：:]/` `/追加[：:]/` の行を抽出。銘柄名→証券コードに変換（既知コードはそのまま、不明は1社ずつ確認）。
   - これで**OCRせずに正確に**構成差分が取れる。図は最終手段。

3. **ビューアへの月追加手順**（`research/reports/高配当株マガジン_月次比較ビューア.html`）：
   - 追加銘柄は `PF_2026` に `"コード":["名称","セクター"]` を追記（名称解決用）。
   - その月の `codes` 配列を作る：前月の配列から除外を抜き、追加を足す（例：`const CODES_JUN = CODES_34.filter(c=>!除外.includes(c)).concat(追加)`）。
   - `MAGAZINE` に `"YYYY-MM": { label:"YYYY年M月（第N回）", codes:その月配列, yield:◯, dividend:◯ }` を追記。
   - footer出典に第N回を追記。

4. **全体利回り・年間配当（yield/dividend）は図の中**：
   - 図（モデルPF表）の summary にのみ数値がある。本文には無いことが多い。
   - 図は投稿の**「続きを読む」展開後**に表示される。Codex in Chrome はブラウザ=read tierで**タブ切替・展開クリックができない**ため、図を読むには**ユーザーに「続きを読む」を1クリック展開してもらう**必要がある（2026-06-08の制約）。
   - 読めたら `computer` の zoom で summary（PF配当利回り%・年間配当）を読み取り `yield`/`dividend` に入れる。**読めない間は暫定で `null`** とし、ビューアは「図解参照」でなく**前月の値を流用せず空欄扱い**にする（※「図解参照」表記はユーザーに不評＝使わない。`null` の月は該当マスを「—（利回りは次回反映）」と明示）。
   - 年間配当 ≒ 元本30万 × 利回り（利回りが取れれば算出可：`Math.round(300000*yield/100)`）。

5. 🚨 **投資助言NG厳守**：差分は「事実の記録」。「買うべき/今が買い時/この配分に」は出さない（digest.md §1ルール3・§4）。

### Part C-2: 自分の保有を l-haitou から自動取り込み（毎回・2026-06-08確立）

🔴 月次比較ビューアの「②自分の保有 vs マガジン」の保有を、毎回 l-haitou から読み取って自動更新する（ユーザーはコピペ不要・l-haitou本体は読むだけ＝無改修）。

1. `https://worksnow.online/l-haitou/dashboard.html` を Chrome で navigate（ログイン/アクセスコード `appAccessCode` 済み前提。未ログインなら案内し中断）。
2. ナビゲーションの「保有一覧」を開き、表示された「保有株式一覧」表の各行から**コード列と銘柄名列**を読み取る。ブラウザのlocalStorage・Cookie・認証情報は読まない。
   - 表のヘッダー行を除外し、4桁のコードがある行だけを対象にする。
   - 同一コードが複数口座にある場合でも、画面上の統合済み1行を1銘柄として数える。
   - 取得額・評価額・損益・配当額などはビューアへ保存しない。保有判定に必要なコードと名称だけを扱う。
3. ビューア `高配当株マガジン_月次比較ビューア.html` の `HOLDINGS_DEFAULT` のコード集合と照合：
   - **コードに変化があれば** `HOLDINGS_DEFAULT` を現在保有で差し替え＋`HOLD_DATE` を当日に。銘柄名はビューア側の整形版を優先（l-haitouは全角・略称で読みにくいので、新規コードのみ補う）。
   - **変化なければ** `HOLD_DATE` だけ当日に更新し「保有：前回から変更なし（N銘柄）」と報告。
   - ビューア内のファイル取込や端末別localStorageは使わない。`l-haitou`を唯一の正本とし、Codexが読み取ったスナップショットをHTMLへ反映する。
4. 🚨 投資助言NG：保有の可視化＝事実の記録のみ。「買うべき」は出さない。l-haitouは worksnow.online（リポジトリ外）なので**読み取り専用**（本体改修はしない）。

## ルール（厳守）

- **礼節アクセス**：記事間 **3秒以上**・分速10件以下（collect.md §6）。UA偽装しない。
- **本文転載禁止**：要約は自分の言葉。台帳・ビューアに本文を貼らない（規約#12・著作権）。
- **私的利用限定**：学長マガジン要約は**自分用メモ**。blog/sns へ勝手に送出しない（送出はユーザー判断／handoff.md）。
- **投資助言NG**：高配当株は事実の記録と可視化のみ。最終判断はユーザー（digest.md §1）。
- **セッション容量**：本文を会話に展開しない。詳細取得は学長1〜2件まで。日課は数分で終える設計。重くなったら「続きは次セッションで」と提案。
- **書き込み範囲**：このスキルが触るのは `research/` 配下（reports/HTML・MEMORY.md 台帳）のみ。他部門ファイルは「TODO追記」だけ（AGENTS.md マルチセッション運用）。
- **確認質問より先に動く**：起動前チェックを通ったら、即 Part A→B→C を実行してサマリー出力（朝会と同じ思想）。
