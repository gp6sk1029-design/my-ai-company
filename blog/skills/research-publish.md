## §7. リサーチルール

### 情報源リスト
- Amazon・楽天のレビュー（星1〜5をまんべんなく）
- X（旧Twitter）のリアルタイム口コミ
- Reddit・Quoraの海外ユーザーの声
- YouTubeのコメント欄
- メーカー公式サイト・スペックシート
- 専門メディアのレビュー記事
- Googleトレンド・Amazon売れ筋ランキング
- Makuake・Kickstarterの注目プロジェクト

### 星1レビューの活用
- 「どこが不満か」＝読者が本当に気にしているポイント
- 星1の不満を先に記事で取り上げ「でもこの使い方なら解決する」と返す構成が強い

### 口コミを記事に組み込む型
- 要約・言い換えで使う（直接引用・コピペ禁止）
- 「多くのユーザーが〇〇と感じている」など集合知として表現
- ネガティブ口コミは「こう使えば解決する」という提案につなげる
- 数字が出ている口コミは積極的に活用

## §8. SEOルール

### キーワード戦略
- メインキーワード1つ・サブキーワード2〜3つを記事作成前に設定
- メインキーワードはタイトル・最初の100文字・H2見出しに自然に含める
- 詰め込みはしない

### タイトル
- 32文字以内を目安
- 数字・金額・「裏話」「実態」「口コミ」で興味を引く
- 例：「【年間8万円の価値】〇〇レビュー｜生産技術視点で徹底検証」
- 例：「【1,000件の口コミを読んだ】〇〇レビュー｜星1から見えた本当の評価」

### メタディスクリプション
- 120文字前後。メインキーワードと記事の一番おいしい部分を含める

### E-E-A-T（経験・専門性・権威性・信頼性）
- 実際に使った経験・数値データを必ず入れる
- 複数の口コミ・情報源を統合した信頼性を示す
- 工場・生産技術の現場経験を根拠として示す

## §9. 文章校正チェックリスト

記事完成後、公開前に以下を必ずチェックする：

### 文章品質
- [ ] 文法・句読点の誤りがないか
- [ ] 一文が長すぎないか（50文字超は分割検討）
- [ ] 同じ意味の繰り返し・冗長表現がないか
- [ ] です/ます調とだ/である調が混在していないか
- [ ] 漢字とひらがなのバランスが適切か

### キャラクター品質
- [ ] オオタニ所長の断言口調が崩れていないか
- [ ] タナカの敬語口調が崩れていないか
- [ ] 1セリフ1メッセージになっているか
- [ ] メタ表現が入っていないか

### 金額・数値
- [ ] 「便利」「効率的」だけで金額換算していない箇所がないか
- [ ] 年間削減金額・回収期間が記載されているか

## §10. ファクトチェック手順

### 検証対象
- 製品名・モデル名・発売日・価格・スペック数値・機能名・技術名

### 情報源の優先順位
1. メーカー公式サイト（最優先）
2. 公式プレスリリース
3. 大手テックメディア（Impress Watch・PC Watch等）
4. Amazon・楽天の公式ストア

### よくある失敗パターン
| 失敗 | 対策 |
|---|---|
| 発売年を推測で書いた | メーカープレスリリースで必ず確認 |
| 価格を「〜万円台」と曖昧に記述 | 定価は税込・税抜を明記 |
| 複数モデルのスペックを混同 | 型番ごとに仕様を確認 |
| バッテリー持続を最良条件だけ記載 | 測定条件を明記 |

## §12. SNS連携（→ `sns/` 配下を参照）

ブログ記事の公開後はSNS3チャネル（X／Instagram／YouTube）で拡散する。
**SNS関連のルール・テンプレート・運用は `sns/SKILL.md` 配下に集約された**（2026-05-02移管）。

### 参照先
- 全体ルール：`sns/SKILL.md`
- X特化（旧§12内容を移管・拡張）：`sns/channels/x/SKILL.md`
- Instagram特化：`sns/channels/instagram/SKILL.md`
- YouTube特化：`sns/channels/youtube/SKILL.md`
- ネタ帳・スケジュール：`sns/calendar.md`

### ブログ部門からのトリガー
記事公開時に「**記事xxxのSNS原稿作って**」とユーザーから依頼される想定。
ブログ統括PDMはこれを受けてsns/側のフローへ移行する。

## §13. アイキャッチ画像ルール

### スコアリング基準（実機写真が複数ある場合）
1. 人・手首着用あり → +3点
2. 画面点灯・表示あり → +2点
3. 正面アングル → +2点
4. 明るさ・ピントが良好 → +1点
5. 裏面・側面のみ → -1点

### 配置ルール
- 全画像を使わず「要所で効果的に」配置
- 配置の基本：スペック紹介直後・装着感セクション・耐久性レポート
- 同じアングルの写真が複数ある場合は最良の1枚だけ

> ⚠️ 画像の事前リサイズ・蓄積防止ルールは [technical.md](technical.md) を参照。
