# 掛け合わせ創造ルール
# 優良記事 × 優良記事 = 新副業アイデア

> ⚠️ このファイルは **掛け合わせ創造の中核ロジック** です。
> 全体像・クイックリファレンスは [research/SKILL.md](../SKILL.md) を参照。
> 収集は [collect.md](collect.md)、自動化提案は [automate.md](automate.md)、他部門連携は [handoff.md](handoff.md) を参照。

---

## §0. このファイルの役割と読むタイミング

優良判定された記事**2件以上**を組み合わせて、新副業アイデアを生成するときに必読。
出力は `research/MEMORY.md`「💡 生成アイデア台帳」+ 副業企画書テンプレ。

工程フロー:
- **入力**: 優良判定（60点以上）の記事2件
- **出力**: 副業企画書1件（MEMORY.md台帳追記） + 4軸スコア
- **完了条件**: 4軸15点以上で「採用候補」、未満で「保留中」マーク

---

## §1. 「優良記事」5指標スコアリング

| 指標 | 配点 | 判定方法 |
|---|---|---|
| **反応数（いいね数）** | 50点 | 上位20% → 50点 / 上位50% → 25点 / それ以下 → 10点 |
| **コメント数** | 15点 | 10件以上 → 15点 / 3-9件 → 8点 / 0-2件 → 0点 |
| **更新頻度** | 10点 | 3ヶ月以内 → 10点 / 6ヶ月以内 → 5点 / 1年超 → 0点 |
| **数値の具体性** | 10点 | 数値3つ以上 → 10点 / 1-2つ → 5点 / 0 → 0点 |
| **自己評価** | 15点 | 「掛け合わせ／自動化の種」と判定 → 15点 / 普通 → 8点 / イマイチ → 0点 |
| **合計** | 100点 | **60点以上で「優良」**マーク（MEMORY.md台帳に記録） |

## §2. 「掛け合わせ」3型

### 2.1 補完型（A×B = 弱点補完）
- 構造: Aの弱点をBが補う
- 例: 「ブログ収益化」(A・収入の波が大きい弱点) × 「コンサル副業」(B・労働集約の弱点) → 「ブログ集客 → コンサル受注」モデル
- 選び方: A・Bは別カテゴリから1つずつ

### 2.2 増幅型（A×B = 強み増幅）
- 構造: A・Bの強みが掛け算で増幅
- 例: 「SNS発信」(A) × 「電子書籍販売」(B) → 「SNSで権威性構築 → KDP販売で印税」モデル
- 選び方: A・Bは同カテゴリから選ぶことが多い

### 2.3 転用型（A×B = 業界横断）
- 構造: A業界の手法をB業界に持ち込む
- 例: 「飲食店の予約システム」(A) × 「メルカリ転売ノウハウ」(B) → 「飲食店オーナー向け転売仕入れ代行」モデル
- 選び方: A・Bは全く異なる業界から

- 損益分岐月数: Xヶ月（= 初期投資 ÷ 月次利益）

## §4. ROI計算ルール（CLAUDE.md準拠・時給950円基準）

- 副業の場合: **本業時給と副業時給の比較**
- 損益分岐月数を必ず明記
- 「年間利益」と「年間時間投入」を**両軸**で出す
- 時給950円は全国最低賃金水準（CLAUDE.md準拠）
- 想定時給 < 950円の副業は「棚上げ」マーク（「最低賃金以下の副業は時間の浪費」原則）

---

## §5. 創造プロセスの再現性確保

- どの記事 × どの記事から生まれたかを必ず `MEMORY.md` に記録
- 同じ組み合わせを2回計算しない（差分のみ追加）
- 同一テーマで複数案出した場合は「派生#N-1, N-2, ...」として枝分かれ管理

---

## §6. 自己採点ルール（4軸スコア）

| 軸 | 5点満点の基準 |
|---|---|
| **実現可能性** | 5点: 1ヶ月以内に着手可能 / 3点: 3ヶ月以内 / 1点: 半年以上 |
| **独自性** | 5点: 他にない / 3点: ニッチに新規性 / 1点: 既存の焼き直し |
| **ROI** | 5点: 想定時給5,000円超 / 3点: 1,500-5,000円 / 1点: 950-1,500円 |
| **リスク低さ** | 5点: 初期投資0円・法規制なし / 3点: 5万円以下 / 1点: 10万円以上 or 法規制要確認 |

**合計15点以上**で「他部門への振り分け候補」昇格 → handoff.md フローへ

---

## §7. 失敗パターン蓄積（机上の空論を防ぐ8項目チェック）

副業企画書を「採用候補」マークする前に、以下すべてYESを付ける。1つでもNGなら「保留中」へ。

- [ ] **想定月収の根拠**が「実在の事例」か「業界相場のレンジ」で示せるか
- [ ] **月次工数**を「具体的なタスク分解」で出しているか（「営業10時間+制作20時間」等）
- [ ] **初期投資の内訳**が明示されているか
- [ ] **5年継続できる確率**を1行でコメントしているか
- [ ] **法規制**（古物商・特商法・宅建等）の確認要否を明記したか
- [ ] **競合の有無**を1行で言及したか
- [ ] **自分（ユーザー）の既存リソース**（スキル・人脈・時間）と適合するか
- [ ] **「やめどき」の数値基準**（月赤字3ヶ月連続等）を書いたか

---

## §8. ユーザー対話プロトコル

- 生成アイデアは**必ずユーザー承認を仰ぐ**（自動採用しない）
- 提示時の構成: 副業企画書テンプレ全文 + 4軸スコア + チェックリスト結果
- ユーザー承認後の選択肢:
  1. 「面白そう、blog記事化したい」→ handoff.md §2 blog連携
  2. 「SNSで発信したい」→ handoff.md §3 sns連携
  3. 「自分で着手する」→ MEMORY.md「マイ副業ポートフォリオ」追加
  4. 「保留」→ MEMORY.md「💡 生成アイデア台帳」状態を「保留中」に
  5. 「不採用」→ 状態を「棚上げ」に

---

## §9. 月次棚卸し

月初に「💡 生成アイデア台帳」を棚卸し：
- 「保留中」が3ヶ月以上滞留 → 「棚上げ」に格下げ
- 「採用候補」のままtools/blog/snsで実装されていない案 → ユーザーに進捗確認
- 「マイ副業ポートフォリオ」と照合し、撤退検討中の副業の振り返り
