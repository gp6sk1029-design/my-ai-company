## §0. このファイルの役割と読むタイミング

**単一の優良記事**から副業ノウハウを抽出し、Claude Code / Claude API / PWA で自動化する設計を提案するときに必読。
出力は `research/MEMORY.md`「🤖 自動化提案台帳」+ 自動化提案書テンプレ → tools/MEMORY.md へ送出。

工程フロー:
- **入力**: 優良判定（60点以上）の記事1件
- **出力**: 自動化提案書1件 + アーキパターン推奨 + ROI試算
- **完了条件**: §14 8項目チェックリスト全YES + 4軸15点以上で tools/MEMORY.md へ送出

## §2. 自動化候補の見極め基準（4ゲート）

優良記事からノウハウを抽出したら、以下4ゲートを上から順に通す。**1つでもNOなら自動化提案は作らず、synthesize.md（掛け合わせ）へ戻す**。

| ゲート | 判定 | NOの場合の扱い |
|---|---|---|
| **G1: 反復性** | 同じ作業を月10回以上やる工程があるか | NO → 自動化価値なし。synthesize（掛け合わせ）へ戻す |
| **G2: 構造化可能性** | 入力・出力がテキスト/数値/画像で表せるか | NO → 接客・体力労働・対面営業は対象外 |
| **G3: 法規制クリア** | 特商法・古物商・著作権・薬機法・景表法・個人情報保護法・不正アクセス禁止法に抵触しないか | NO → §12禁止領域へ。代替案を併記 |
| **G4: ROI閾値** | 月削減時間 × 時給950円 > 月運用コスト（API+Workers）× 3倍 | NO → 「保留中」台帳。閾値到達時に再評価 |

---

## §3. ノウハウ抽出ロジック（工程分解の3ステップ）

優良記事の本文要約（`MEMORY.md` 500字要約）から、以下3ステップで工程を棚卸す。

### Step 1: 工程の時系列分解
記事の「やり方」を **「動詞 + 目的語」**の単位に分解し、所要時間と頻度を併記。

| # | 工程（動詞+目的語） | 所要時間 | 頻度 | 入力 | 出力 |
|---|---|---|---|---|---|
| 1 | 商品リストを取得する | 15分 | 毎日 | URL一覧 | CSV |
| 2 | 価格を比較計算する | 5分 | 毎日 | CSV | 利益額 |
| 3 | 出品文を書く | 20分 | 毎日 | 商品名 | テキスト |
| 4 | メルカリに出品する | 10分 | 毎日 | テキスト+画像 | 出品URL |

### Step 2: 自動化可否マーキング
各工程に [🤖自動化可能 / 👤人手必須 / 🔄半自動（承認ゲート要）] のいずれかを付ける。
判定基準は §2 4ゲート＋ `tools/SKILL.md`「絶対にやってはいけないこと」を参照。

### Step 3: 削減時間の合計
🤖と🔄の合計時間 × 月頻度 = **月削減時間（H）**。
H × 950円 = **月削減金額（円）**。
これが §11 ROI再計算の入力になる。

## §4. 自動化アーキ4パターン選定マトリクス

| 条件 | 推奨パターン |
|---|---|
| 月10回未満・ユーザー手動起動でOK | **A: Claude Code単発スクリプト** |
| エンドユーザー（家族・自分以外）が触る | **B: PWA + Cloudflare Workers** |
| 夜間バッチ・人が見ていない時間で動かす | **C: cron + Claude API** |
| WP/メルカリ/Google等の既存セッションを使う | **D: Claude in Chrome自動化** |
| 上記が混在 | A→B→Cの順で段階的にスケールアップ |

> 🔴 **4パターンとも CLAUDE.md 固定構成（Cloudflare Workers + D1 + Access + Opus）に準拠**。
> 別技術スタック（Vercel, Supabase, Lambda等）は提案禁止。
> 詳細判断は CLAUDE.md「AI操作の優先順位」§「判断フロー3問」と一致させる。

## §5. パターンA: Claude Code単発スクリプト

**雛形**: `blog/scripts/article_status.py` / `tools/ec/scripts/price_calculator.py`

**提案時に書く項目**:
- ファイル名案: `tools/{ツール名}/scripts/{機能名}.py`
- 引数: `--input`, `--output`, `--dry-run` 等
- 出力先: ローカルファイル or 標準出力
- 実行例: `python3 tools/xxx/scripts/yyy.py --input data.csv`

**メリット**: 最も軽量・無料・即実装
**デメリット**: ユーザーがCLIで都度起動が必要

---

## §6. パターンB: PWA + Cloudflare Workers

**雛形**: `tools/cooking-recipe/` / `tools/life-plan/`

**提案時に書く項目**:
- ディレクトリ案: `tools/{ツール名}/`
- フロント: PWA（`public/index.html` + Service Worker）
- バック: Cloudflare Workers（`functions/index.ts`）
- DB: D1（`schema.sql` 概要）
- 認証: Cloudflare Access（特定メアドのみ許可）
- wrangler.toml の主要項目: name, compatibility_date, d1_databases

**メリット**: スマホから使える・家族・チーム共有可能
**デメリット**: 実装工数が大きい（10時間〜）

---

## §7. パターンC: cron + Claude API（バッチ処理）

**雛形**: （まだ部門内に実例なし）`blog/scripts/article_from_meshi.py` を毎時起動するイメージ

**提案時に書く項目**:
- Cloudflare Cron Trigger 設定例: `* */6 * * *` （6時間ごと）
- 1実行あたりトークン目安: 入力XXk + 出力XXk = XXkトークン
- 月額試算: トークン単価 × 月回数（Opus基準）
- 失敗時のリトライ・通知方法（Gmail送信等）

**メリット**: 完全自動化・人が見ていない時間で動く
**デメリット**: APIコストが月数百〜数千円かかる（要試算）

---

## §8. パターンD: Claude in Chrome 自動化

**雛形**: `tools/ec/scripts/mercari_browser.py` / `tools/ec/scripts/mercari_selenium.py`

**提案時に書く項目**:
- 操作対象URL: 例 `https://example.com/admin`
- ログイン状態前提: ユーザーが事前にChromeでログイン
- アクセス間隔: 3秒以上（収集対象サイト運営への礼節）
- 操作シーケンス: クリック→入力→確認ボタン→結果取得

**メリット**: 既存セッションを再利用・追加認証不要
**デメリット**: UI変更で壊れる・スクレイピング規約に注意

## §11. ROI再計算（自動化前後の損益分岐）

```
月削減時間 = (🤖工程の合計時間 + 🔄工程の合計時間) × 月頻度
月削減金額 = 月削減時間 × 950円
月運用コスト = Claude API月額 + Cloudflare月額（無料枠超過分）

月利益 = 月削減金額 - 月運用コスト
損益分岐月数 = 初期実装工数（時給950円換算） ÷ 月利益
5年累計純益 = 月利益 × 60ヶ月 - 初期実装工数換算
```

**閾値**:
- 月利益 > 月運用コスト × 3倍（§2 G4と整合）
- 損益分岐月数 6ヶ月以内が望ましい
- 5年累計純益が初期実装工数の5倍以上

## §12. 自動化禁止領域（人間判断必須）

以下は §14 で承認ゲートを必須にしても、**全自動化は禁止**：

| 領域 | 理由 |
|---|---|
| **顧客対応・クレーム対応** | 炎上リスク・人間関係の機微判断必要 |
| **投資判断・契約締結** | 不可逆な金銭事故リスク |
| **人事評価** | 差別リスク・透明性問題 |
| **法令違反の可能性がある業務** | §2 G3 NG領域 |
| **医療・健康アドバイス** | 薬機法・医師法 |
| **金銭の自動送金** | 不正・誤送金リスク |
| **公開コンテンツの自動投稿（承認なし）** | 誤情報拡散リスク |

これらに該当する工程は §3 Step2 で必ず **👤人手必須** マーク。

## §13. 既存tools/との重複チェック手順

新規自動化提案を起こす前に、`research/MEMORY.md`「🔍 既存ツールとの重複チェック表」と機能照合：

1. 提案する自動化の主機能を一文で言語化
2. 重複チェック表の各行と照合
3. 重複あり → 「拡張提案」に書き換え（既存ツールに機能追加する形）
4. 重複なし → 「新規ツール提案」として進める

**月初棚卸し**: `tools/SKILL.md`「担当範囲」表と本表を照合し、差分があれば research/MEMORY.md「進化ログ」に記録。

## §14. 机上の空論を弾く8項目チェックリスト（自動化版）

提案を tools/ へ送出する前に、以下すべてに **YES** を付けること。1つでも **NG** なら送出保留。

- [ ] **① Claude APIコスト試算**: 月額をトークン単価で実数試算したか（仮想ではなく）
  - 500円以下: OK / 500-2000円: 要承認 / 2000円超: パターンA(CLI)へ降格検討
  - 🔴 Sonnet/Haiku への変更は禁止（CLAUDE.md「Claude Opus固定」準拠）
- [ ] **② Cloudflare無料枠の範囲**: Workers Requests 10万/日, D1 5GB, Cron 5本/account の範囲か
- [ ] **③ 既存tools/との重複なし**: §13 で照合済み
- [ ] **④ 承認ゲート設計**: 金銭・投稿・送信など外部影響のある操作に人間承認ゲート（tools/ec/SKILL.md §9同型）
- [ ] **⑤ dry-runモード**: 本番動作前に空打ち確認できる構造
- [ ] **⑥ 法規制チェック**: §2 G3 の7法令を1つずつ該当有無明記
- [ ] **⑦ 撤退条件**: 「いつ自動化を止めるか」の数値基準（月赤字3ヶ月連続等）を書いた
- [ ] **⑧ セッション容量**: Claude Codeから起動される場合、画像Read/出力サイズ上限を設定（CLAUDE.md「セッション容量管理」準拠）
