## §0. このファイルの役割と読むタイミング

リベシティから記事を収集する **すべてのフェーズ**で必読。
ログイン確認 → 一覧取得 → 詳細取得 → MEMORY登録のフローを定義する。

工程フロー:
- **入力**: リベシティのログイン済みブラウザ + 収集対象カテゴリ
- **出力**: research/MEMORY.md「収集済み記事台帳」への追記
- **完了条件**: 取得記事のIDがMEMORY.md台帳に重複なく登録されている

## §1. データソース定義

| 項目 | 内容 |
|---|---|
| URL | `https://libecity.com` |
| 認証 | ログイン必須（有料会員想定） |
| 対象 | ノウハウ図書館（カテゴリ別記事） |
| アクセス手段 | Claude in Chrome MCP（既存ログインセッション再利用） |

> ⚠️ URL構造は実際のリベシティに合わせて運用開始時に確認。

## §2. Claude in Chrome 起動フロー（5ステップ）

### Step 1: Chrome MCP接続確認
- `mcp__Claude_in_Chrome__list_connected_browsers` でブラウザ接続を確認
- 未接続 → ユーザーに「Chrome拡張を起動してください」と案内し中断

### Step 2: ログイン状態確認
- `https://libecity.com` にアクセス
- ログイン状態の判定:
  - ログイン済み: マイページへの遷移ボタンが表示される
  - 未ログイン: ログインフォームが表示される
- 未ログイン → ユーザーに「リベシティに手動ログインしてください」と案内し中断
  - 🔴 **重要**: パスワード入力はユーザーが行う（CLAUDE.md安全ルール準拠）

### Step 3: ノウハウ図書館遷移
- ノウハウ図書館URL（実URL確認後§1に記録）に遷移
- `mcp__Claude_in_Chrome__get_page_text` でカテゴリ一覧を取得

### Step 4: 記事一覧取得（軽量モード）
- 指定カテゴリで最大50件のタイトル+URL+反応数を取得
- 構造化スキーマ（後述§5）でJSON化
- **本文は取得しない**（コンテキスト節約）

### Step 5: 記事詳細取得（重量モード）
- ユーザー承認後、上位5件のみ詳細取得
- `get_page_text` で本文を取得
- 本文は500字以内に要約してからMEMORY.mdへ登録
- 全文を会話に展開しない（CLAUDE.md「セッション容量管理」準拠）

## §3. 1セッションあたりの取得上限

| モード | 1件あたりのトークン目安 | 上限 |
|---|---|---|
| 一覧スクレイプ（タイトル+URL+反応数のみ） | 約100トークン | **50件**（5,000トークン） |
| 詳細取得（本文500字要約してMEMORY追記） | 約2,000トークン | **5件**（10,000トークン） |
| 詳細取得（本文全文を会話展開）❌禁止 | 約10,000トークン | **禁止** |

**目安**: 1セッション合計15,000トークンまでに抑える。これを超えそうな場合は「次セッションに分割」を提案。

## §4. 重複検出ロジック

1. `research/MEMORY.md` の「収集済み記事台帳」をパース
2. 記事IDを集合化
3. 新規取得記事のIDが既存集合に含まれるかチェック
4. 含まれる場合の選択肢:
   - 収集スキップ（デフォルト）
   - 更新確認のみ（いいね数・コメント数が変わった場合のみ更新）
   - 再取得（記事内容が大幅更新された場合）

**Phase 2スクリプト化候補**: `research/scripts/dedup_check.py`（`blog/scripts/article_status.py` の曖昧検索パターン応用）

## §5. 取得データの構造化スキーマ

各記事を以下の形式で `MEMORY.md`「収集済み記事台帳」に登録：

```yaml
- 記事ID: (リベシティ内のユニークID)
  URL: (記事の完全URL)
  タイトル: (記事タイトル)
  カテゴリ: (リベシティ上のカテゴリ名)
  著者: (執筆者名・ハンドル名)
  公開日: YYYY-MM-DD
  更新日: YYYY-MM-DD
  いいね数: (数値)
  コメント数: (数値)
  本文要約: (500字以内)
  全文URL: (記事のURL再掲)
  スコア: (5指標で採点・合計100点満点)
  評価: (優良/普通/イマイチ)
  収集日: YYYY-MM-DD
```

## §6. リベシティ利用規約・礼節ルール

| ルール | 内容 |
|---|---|
| **アクセス間隔** | 1記事につき**3秒以上**の待機（合計でも分速10件以下） |
| **時間帯配慮** | 時間帯制限なし（2026-05-28ユーザー指示で撤廃）。深夜帯も3秒間隔・分速10件以下の礼節アクセスは維持（規約禁止#22「過度の負担」配慮） |
| **コピペ転載禁止** | 記事本文を**そのまま外部に出さない**。要約・引用は元URL明記 |
| **自分用利用に限定** | 統合アイデアの**元記事タイトル・URL**は他部門に渡してもよいが、**本文の転載は禁止** |
| **utm/referer** | 通常のブラウザアクセスとして振る舞う（特殊ヘッダ・User-Agent偽装しない） |
| **規約確認の更新** | 半年ごとにリベシティ利用規約を再確認し MEMORY.md に記録 |

🔴 **起動前必須**: `research/MEMORY.md`「ユーザー承認記録」が空欄なら **収集を一切行わない**。

## §7. セッション容量への配慮

| リスク | 対策 |
|---|---|
| 記事を会話に取り込みすぎる | 詳細取得は5件/セッション上限・本文は500字要約のみ |
| MEMORY.md が肥大化 | 月1回の棚卸しで「採用棚上げ」アイデアをアーカイブ移動 |
| 取得記事を Read する度に蓄積 | Read で記事本文を再読しない。MEMORY.mdの要約だけ参照 |
| 10件超で /compact 提案 | コンテキスト残量が60%を切ったらユーザーに `/compact` 提案 |

## §8. 失敗時の対処

| 失敗パターン | 原因 | 対処 |
|---|---|---|
| ログインできない | セッション切れ・パスワード変更 | ユーザーに手動再ログイン依頼 |
| ページが404になる | 記事削除・URL変更 | 該当記事を台帳で「削除済み」マーク |
| 大量取得でブロック | アクセス頻度超過 | 24時間休止 + アクセス間隔を5秒に延長 |
| WAF検知 | User-Agent等の異常 | 通常ブラウザアクセスに戻す・偽装禁止 |
| ノウハウ図書館のUI変更 | リベシティ側の改修 | §1にURL・セレクタを再記録、Step 3を改訂 |
| 最新でない投稿を最新と誤認 | get_page_textがページ途中のarticle要素を返す（チャット形式で位置ズレ） | 取得後に必ず本文中の日付を確認し、最新位置を特定してから要約（2026-05-28学習） |

## §8.5. 取得のコツ（2026-05-28 実運用で確立）

学長マガジン等の長文チャットを Claude in Chrome で取る際の実証済みノウハウ：

| コツ | 内容 |
|---|---|
| **結果は約3000字で打切り** | `get_page_text`・`javascript_tool` の結果表示は約3000字で切れる。長い投稿を一度には取れない |
| **最新位置の特定** | `innerText` を日付（例 `2026/05/28`）で `indexOf` し、その投稿だけを切り出す。チャットは最新が途中表示されるため必須 |
| **構造抽出で全問取得** | Q&Aは `❓️` で split → 各Qの「質問＋回答冒頭150字」を配列化。前半 `slice(0,5)`／後半 `slice(5)` の2回で全10問をカバー |
| **本文は要約のみ** | 取得した全文は会話・MEMORYに転載せず digest.md §3 形式で要約（規約・著作権・容量の三立） |
